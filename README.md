# Лаборатори 3 — Чанарын сценарио, SLO, k6 threshold

**Оюутан:** Ган-Оргил  
**Оюутны код:** B232270091  
**Хичээл:** F.CSA313 — Программ хангамжийн чанарын баталгаа ба тест

Энэ ажлаар локал API-ийн чанарын шаардлагыг хэмжиж болох сценарио болгон бичиж, SLO болон k6 threshold руу шилжүүлнэ. API нь сагсанд нэмэх, тайлан авах, төлбөр хийх гэсэн гурван үйлдэлтэй. Төлбөрийн хүсэлтийн ойролцоогоор 5% нь зориуд 500 алдаа буцаана. Тайлангийн хариуг 200–400 мс саатуулна.

## Чанарын сценарио

### 1. Performance — сагсанд нэмэх

| Хэсэг | Сценарио |
| --- | --- |
| Тойм | Хэрэглэгч бараагаа сагсанд нэмэхэд хариу удаан хүлээхгүй байх. |
| Системийн төлөв | API ассан, `/cart/add`, `/report`, `/pay` endpoint ажиллаж байгаа. |
| Орчны төлөв | Нэг машин дээр 20 VU тогтмол ажиллана. VU бүр гурван хүсэлтээ дарааллаар явуулаад 1 секунд хүлээнэ. Тайлангийн хүлээлттэй нийлээд ойролцоогоор 45–47 хүсэлт/с үүснэ; `/cart/add` нь ойролцоогоор 15 хүсэлт/с. |
| Гадаад өдөөлт | Хэрэглэгч `POST /cart/add` хүсэлт явуулах. |
| Шаардлагатай хариу | HTTP 200 болон `{"ok":true,"items":1}` буцаах. |
| Хэмжүүр | 1 минутын турш `/cart/add` хүсэлтийн хариу хугацааны p95 < 20 мс байх. |

### 2. Reliability — төлбөр хийх

| Хэсэг | Сценарио |
| --- | --- |
| Тойм | Төлбөрийн үйлдлийн бүтэлгүйтэх магадлалыг зөвшөөрөгдөх хэмжээнд барих. |
| Системийн төлөв | API ажиллаж байгаа, төлбөрийн handler хүсэлтийн ойролцоогоор 5%-д 500 алдаа үүсгэдэг. |
| Орчны төлөв | 20 VU, гурван endpoint оролцсон ижил ачаалал, 1 минутын хэмжилт. |
| Гадаад өдөөлт | Хэрэглэгч хэвийн `POST /pay` хүсэлт явуулах. |
| Шаардлагатай хариу | Амжилттай үед HTTP 200 болон `{"paid":true}`; алдаатай үед HTTP 500 буцаах. |
| Хэмжүүр | `/pay` хүсэлтийн алдааны хувь буюу POFOD < 8% байх. |

### 3. Availability — серверийн гэнэтийн зогсолт

| Хэсэг | Сценарио |
| --- | --- |
| Тойм | Сервер гэнэт зогссон үед хүртээмж болон эргэн сэргэх хугацааг хэмжих. |
| Системийн төлөв | API болон k6 ачааллын тест ажиллаж байгаа. |
| Орчны төлөв | 20 VU, 2 минутын цонх. Тестийн дунд серверийн процессыг зогсоож, 10 секундийн дараа дахин асаана. |
| Гадаад өдөөлт | Серверийн процесс гэнэт зогсох буюу crash болох. |
| Шаардлагатай хариу | Сервер дахин асахад өмнөх гурван endpoint хүсэлт хүлээж авч эхлэх. |
| Хэмжүүр | Амжилттай хүсэлт / нийт хүсэлт ≥ 90%. VU бүрийн эхний бүтэлгүй сагсны хүсэлтээс дараагийн амжилттай хүсэлт хүртэлх хугацааны p95 < 12 секунд байх. |

### 4. Нэмэлт performance — тайлан авах

| Хэсэг | Сценарио |
| --- | --- |
| Тойм | Тайлангийн зориудын саатлыг тооцоод хариу хугацаанд хязгаар тавих. |
| Системийн төлөв | `/report` хүсэлт бүр 200–400 мс хүлээлттэй. |
| Орчны төлөв | 20 VU, 1 минут, бусад хоёр endpoint-той ижил давталтаар ажиллана. |
| Гадаад өдөөлт | Хэрэглэгч `GET /report` хүсэлт явуулах. |
| Шаардлагатай хариу | HTTP 200 болон `{"rows":20000}` буцаах. |
| Хэмжүүр | Тайлангийн хариу хугацааны p95 < 450 мс байх. |

Сценарио бүрд хэрэглэгчийн үйлдэл эсвэл серверийн эвдрэл, ачаалал, ажиглах хариу, тоон хэмжүүрээ тусад нь бичсэн. Ингэснээр шаардлага нь итгэмжтэй, хэрэглэгчид үнэ цэнэтэй, тодорхой, нарийн, ойлгомжтой гэсэн таван шинжийг хангаж байгаа эсэхийг шалгаж болно.
